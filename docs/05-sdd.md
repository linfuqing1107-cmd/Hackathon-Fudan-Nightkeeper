# SDD：Software Design Description

版本v0.1，设计草案。实现行为以Spec为准，字段以数据契约为准。技术版本在T01锁定并记录lockfile，不在此虚构已经验证的库兼容性。

## 1. 架构决策

首版采用TypeScript模块化单体：Next.js网页和同源Route Handlers，PostgreSQL存储，schema库作运行时校验，SQL迁移管理结构，独立Node worker处理DB队列。选择单体降低接口和部署成本，保留设备、规则、摘要的模块边界。

本地计划Docker Compose启动PostgreSQL、web、worker。应用依赖锁定后提供真实一键启动命令。Redis、消息中间件、微服务和原生App均不引入首版。

逻辑组件：

```text
患者/医护浏览器
       |
同源Web + API ----- 身份/患者范围授权
       |
应用服务 ---------- 审计
       |
PostgreSQL (业务记录 + 事务job队列)
       |
Worker -> 质量检查 -> 基线/规则 -> 任务服务
       |                              |
模拟设备适配器                  摘要服务 -> 模板 / 可选模型
```

## 2. 模块及责任

| ID / 模块 | 输入输出 | 不负责的内容 |
| --- | --- | --- |
| D01 identity | 会话 -> actor、workspace、allowedPatientIds | 不接受前端角色覆盖 |
| D02 ingestion | adapter记录 -> 标准Observation、job | 不判精神症状，不静默补值 |
| D03 quality | 时间/覆盖/来源 -> quality、reason | 不把缺失作为0 |
| D04 rules | 冻结基线、有效观测、自报、时钟 -> Evaluation | 不调用LLM，不开药 |
| D05 tasks | Evaluation/主动请求 -> Task、Followup | 不发送真实紧急通知 |
| D06 summary | 有范围的证据 -> 可审阅草稿 | 不拥有风险判断权、不改变任务状态 |
| D07 demo | seed、clock、scenario -> 隔离合成空间 | 不访问附件或真实健康数据 |
| D08 ui | API DTO -> 列表、趋势、表单与任务状态 | 不自行另算阈值或授权 |

建议代码目录：apps/web、apps/worker、packages/domain、packages/contracts、packages/db、packages/adapters、packages/summary、demo、tests。暂不建立空壳应用，以T01最终脚手架为准。

## 3. 数据流与事务边界

### 3.1 数据进入

鉴权及授权 -> 全批schema校验 -> 事务插入Observation并写Job -> 提交 -> 202/成功响应。任一记录非法整批拒绝；相同记录重复不产生额外业务效果。撤回检查与插入共享患者级锁，防止撤回并发继续采集。

### 3.2 规则执行

worker用FOR UPDATE SKIP LOCKED领取job，设置租约。规则执行按患者加事务级锁，取特定版本数据、质量和冻结基线，生成输入哈希。已有同键Evaluation则no-op；新Evaluation与Task创建或更新同事务提交。

数据库部分唯一索引限制(workspaceId,patientId,type)仅一张非终态任务。两个worker即使重复执行，也不会双建单。所有外键检查workspace一致性，由应用层与复合约束共同执行。

首版观察期只处理结束日；R02使用显式时钟，定时每15分钟检查或由演示推进触发。任务逾期只是业务待办，不在无人值守原型中宣称临床响应保障。

### 3.3 人工处置

鉴权 -> 任务范围 -> 锁行并核对version和owner -> 验证状态迁移 -> 更新task及追加audit -> 提交。两个医护同时认领时仅一人成功，另一人409并刷新。Followup追加保存，关闭动作引用既有记录；任何失败均不半关闭。

### 3.4 AI 摘要

生成结构化事实列表，每条分配sourceId。模型只能输出“观察事实、待核实问题”两类内容，不得输出诊断、概率或调药。自由文本视为数据，不能变成工具指令。模型无数据库写权和外部工具权。

返回格式为items[{kind,sourceIds,text}]；引用必须属于当前患者和快照，数值必须对应事实。文字语义安全不能仅靠schema保证，因此所有模型结果保持DRAFT，由医护审核，不自动发给患者。无密钥默认模板。显示生成方式、时间和来源。

## 4. 安全设计

- 服务端对每条患者资源强制范围授权；数据库UUID不能代替授权。
- 本地演示身份开关不用于公网。公网使用服务端认证、隔离空间、CSRF防护、限流及合成数据横幅。
- 上传接口仅模拟器服务身份可用；首版不允许文件上传和任意URL抓取。
- 问卷和药物自由文本不写请求日志，不存localStorage，不加入分析埋点。
- 数据库凭据通过环境配置；提供.env.example但无真实值；CI执行secret scan。
- API限流建议读60次/分钟、写30次/分钟/会话，摘要5次/分钟，作为演示配置接受负载测试校正。
- 真实医疗部署前另做伦理、安全、合规及跨境审查；本文不是合规认证。

## 5. 时间、故障与运维

Clock接口返回UTC瞬时与业务时区，SystemClock用于未来运行，DemoClock用于固定案例；测试禁止依赖系统日期。应用重启不重置演示时钟。

进程中断导致job租约过期可重领；重试不生成重复任务。数据库不可用返回503，前端保留当前未提交内容且不显示成功。规则失败显示待计算状态；模型失败不影响规则。同步断开显示最后同步时间。

观测指标：job失败数、同步延迟、规则耗时、HTTP错误、幂等冲突、摘要降级率。日志只含requestId和伪名资源ID。真实部署的备份周期、恢复目标和保留期未定义，构成上线门槛。

## 6. 测试与部署边界

单元测试用Vitest，接口测试用测试PostgreSQL，端到端用Playwright；具体版本T01验证后锁定。CI运行静态检查、契约、单元、数据库集成和核心E2E，禁止用通过lint代替业务验证。

首版默认本地展示。公网发布为独立里程碑：HTTPS、认证、隔离重置、滥用限制、只含合成数据，禁止直接暴露管理员重置接口。静态截图不作为可运行原型的替代。

## 7. 设计决策记录

| ADR | 决策 | 替代方案及取舍 |
| --- | --- | --- |
| ADR-01 | 模块化单体 | 微服务增加首版运维与一致性成本，暂不采用 |
| ADR-02 | PostgreSQL + 持久job | SQLite方便但多人并发与任务约束验证不同；选择统一测试和部署引擎 |
| ADR-03 | 规则独立于LLM | LLM不承担阈值和任务状态，保证重放和解释 |
| ADR-04 | 冻结个人基线 | 滚动基线可能吸收持续异常，首版不自动更新 |
| ADR-05 | 一个模拟设备来源 | 先验证契约和流程，真实接入需要额外授权 |
| ADR-06 | Web响应式双端 | 原生App涉及商店与后台权限，首版用浏览器完成反馈 |
| ADR-07 | 保留修订历史 | 覆盖旧值破坏证据，修订触发显式重算和复核 |
