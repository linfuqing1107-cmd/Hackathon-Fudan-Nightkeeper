# Spec：可验收行为规格

规范词：必须表示验收要求；建议表示可调整设计。所有数值规则均为合成演示配置，不可用于临床。

## 1. 需求与验收

| ID | 必须实现的行为 | Given / When / Then 验收摘要 |
| --- | --- | --- |
| FR-01 | 服务端身份与患者范围授权 | 医护未获分配 / 访问患者任一资源 / 返回404，不泄漏资源是否存在 |
| FR-02 | 幂等观测接入 | 相同来源记录 / 重复导入 / 不增加观测或任务；冲突载荷返回409 |
| FR-03 | 质量先于分析 | 某日无活动覆盖 / 执行规则 / 保留空值，禁止参与低活动判断 |
| FR-04 | 可追溯个人基线 | 完成冻结基线 / 进入观察期 / 当前观测不进入自身比较基线 |

## 2. 基线与窗口

演示参考日固定为 2026-09-12，时区 Asia/Shanghai。逻辑时钟可通过管理员显式推进，不读取系统当天来改变场景结果。

- 装载基线窗口 2026-08-15 至 2026-08-28，连续14个日历日。
- 首版基线按指标独立判定：窗口内至少10个有效日才为 READY；否则 INSUFFICIENT。
- 基线为有效日中位数；无有效值或中位数为0时，不计算百分比变化。
- 演示观察期为 2026-08-29 至 2026-09-11，只分析已结束的当地日期。
- 有效日不足不能补零；基线、参与观测ID、设备和规则版本均冻结。
- 首版没有自动滚动重建基线；数据更正需管理员显式重算，生成新基线版本。
- 14日、10有效日是测试参数，未来真实队列的14至28天窗口须另行确定。

## 3. 演示规则 v0.1

### R01：持续多维变化核实

对最近连续3个已结束日逐日检查：睡眠有效且比个人中位数减少至少120分钟，同时 EMA 精力为3或4。三天均成立时创建 CHANGE_REVIEW。EMA 缺失或任一天睡眠无效则结论为 INSUFFICIENT，不判正常也不触发。

任务证据包含每日睡眠、基线、差值、EMA修订ID及规则版本。服药异常仅作为补充事实，不作为 R01 必需条件。不得把任务名称写成躁狂、复发或危险。

### R02：同步中断核实

逻辑时钟距最后成功同步严格超过48小时，产生 DATA_QUALITY 任务。恰好48小时不触发。恢复同步且恢复日有有效数据后标记恢复建议，仍需人工关闭。

### R03：连续未服药自报核实

连续2个已结束日期存在明确 NOT_TAKEN 自报时创建 MEDICATION_REVIEW。UNKNOWN、未填写及“提醒已读”都不满足。没有药物名称或剂量推断，不建议补服或调药。

### R04：主动求助

主动请求立即创建 HELP_REQUEST，绕过基线与 R01。演示中只建立任务，不向外发消息；界面显示“演示请求，未联系真实医护；如有紧急情况请使用当地急救或现有就医渠道”。

## 4. 规则执行及迟到数据

按患者串行执行规则；同一事务落入 evaluation 和任务变化。唯一 evaluation 键为患者、规则版本、目标日期、输入摘要哈希。普通同日重放不新增。

迟到或修订数据触发目标日及其后受窗口影响日期重算。原 evaluation 变为 SUPERSEDED，不删除。已建立的任务不自动撤销，追加“证据已修订，需重新核实”；关闭任务不自动重开，必要时生成带 predecessorTaskId 的新核实任务。

## 5. 状态机

任务状态：OPEN -> IN_REVIEW -> WAITING_FOLLOWUP -> IN_REVIEW -> CLOSED。允许 IN_REVIEW 直接关闭；禁止 OPEN 直接关闭。重复任务可由医护从非关闭状态转 MERGED，必须提供同患者、同类型的开放目标任务和原因，禁止形成合并环。

- OPEN 无负责人；认领后为 IN_REVIEW，负责人为当前医护。
- WAITING_FOLLOWUP 必须有下一次联系时间；联系未果可使用此状态，不算 CLOSED。
- CLOSED 必须有核实原因、处置摘要和 outcome；outcome 为 RESOLVED、REFERRED、FALSE_SIGNAL、UNREACHABLE_AFTER_ATTEMPTS。最后一种必须提供尝试记录及关闭理由，不计入“已解决”。
- 仅负责人可迁移任务状态；管理人员可调整分配，但需记录原因。
- 同患者同类型最多一个非终态任务，数据库唯一约束兜底。
- 终态不回退；复发同类变化创建新任务并链接前单。
- 即使数据恢复也不自动关闭任务。

授权状态：GRANTED -> REVOKED。重新授权生成新版本，不复用旧授权时间。演示退出不等于已删除数据，删除申请单独登记；公开演示的合成数据可通过空间重置清理。

## 6. 非功能需求

| ID | 验收要求 |
| --- | --- |
| NFR-01 | 公共展示只含合成数据；密钥与附件不入库；日志不输出问卷正文、令牌或完整请求体 |
| NFR-02 | 固定种子可重放；所有计算有时间、输入引用和版本；规则不依赖LLM |
| NFR-03 | 100名合成患者、每人90日记录、10并发下，列表/详情服务端p95不超过1秒，记录测试环境；摘要接口异步不计入此门槛 |
| NFR-04 | 桌面1440及手机390宽度无正文遮挡；表单与任务流键盘可操作，错误有文字说明 |
| NFR-05 | DB提交成功前不得显示保存成功；进程重启保留任务；后台失败可重试且不重复建单 |
| NFR-06 | 无模型密钥、超时或供应商错误时3秒内启动模板降级；来源标记 TEMPLATE，不伪装AI |
