# PRD：精神卫生院外随访工作台

版本 v0.1；状态：设计草案；责任角色：产品负责人、临床负责人、技术负责人。角色已定义，具体人员未指定。

## 1. 问题与目标

院外两次复诊之间，患者的睡眠、活动、自报症状和服药反馈分散。医护需要识别值得联系核实的变化，同时避免把设备故障当作病情恶化。

首版要证明：数据有质量标记，变化有可追溯依据，任务有负责人，人工处置有记录。它是随访工作流原型，不是已验证的医疗预测器。

产品目标：

- G01：三类合成场景均能完成从数据进入到任务处置的可重复演示。
- G02：每个变化提示可追溯到观测日期、数值、基线与规则版本。
- G03：缺失不会自动变为低活动，未打卡不会自动变为未服药。
- G04：患者只能访问自身信息，医护只能访问分配给自己的患者。
- G05：没有模型密钥、厂商账户或网络时，核心演示仍可运行。

临床有效性、误报容忍度、入组标准及适用病种均须后续独立验证，不是本次原型验收结果。

## 2. 用户与权限

| 角色 | 主要动作 | 禁止动作 |
| --- | --- | --- |
| 演示患者 | 查看本人任务与记录；提交 EMA 和服药反馈；管理演示授权 | 看他人资料；编辑医护记录；修改规则 |
| 医护 | 查看受分配患者；核实、记录、认领及关闭任务；审阅摘要 | 修改患者原始自报；自动开药；跨范围访问 |
| 管理员 | 配置分配关系、演示场景、规则开关；查看运行状态 | 默认读取临床正文；删除审计痕迹 |

管理权限不自动包含医护权限。首版本地切换演示身份可用，公开部署必须启用服务端身份验证和会话隔离。

## 3. 范围与非目标

P0：合成数据接入、质量检查、患者反馈、个人基线、确定性演示规则、工作台、任务闭环、权限、审计、案例重置。

P1：带证据引用的 AI 摘要、只含合成数据的 CSV 导出、响应式体验完善。

不在首版范围：原生 App、多设备真实授权、HIS 对接、真实患者入组、模型训练、复发概率、自动诊疗、家属短信、原始 GPS、通信数据、皮电和皮温研究。

## 4. 关键用户旅程

### 患者每日反馈

打开今日页面，看到待填 EMA 和服药反馈；完成后即时得到保存状态。重复点击不能产生重复记录。无网络时保留当前页面输入并提示未提交，不显示成功，也不在浏览器持久缓存敏感表单。

EMA 示例仅用于演示：情绪、精力、睡得少是否仍不困、主观困扰。采用 0-4 的固定枚举，允许“不愿回答”，不计算诊断总分。具体题目与措辞上线前须临床审阅。

### 医护核实变化

打开待办，先看任务性质和数据是否充分；进入患者详情，核对趋势与规则证据；认领任务并记录联系结果、核实原因和下一步。任务关闭必须留下结果，联系未果不能算问题已解决。

### 设备掉线

列表标为数据质量待核实，趋势显示空缺；建立技术核实任务。不能产生因“步数为零”导致的临床变化任务。

## 5. 页面信息架构

| 页面 | 必备内容与状态 |
| --- | --- |
| 医护待办 | 类型、患者代号、触发时间、负责人、处理状态；空、加载、错误、无权限 |
| 患者列表 | 最后同步、有效天数、未完成任务；搜索和状态过滤 |
| 患者详情 | 睡眠与活动趋势、基线状态、自报、服药、质量、历史随访；缺失区间明确断线 |
| 任务详情 | 冻结的触发证据、认领、核实记录、等待回访、关闭或合并 |
| 患者今日 | 简短问卷、服药反馈、保存与重试、演示求助入口 |
| 设备与授权 | 数据来源、同步时间、授权状态、撤回说明 |
| 管理页面 | 演示场景装载与重置、身份分配、规则版本、运行错误 |

界面采用中文、紧凑表格和清晰趋势图。状态不能仅用颜色表达。目标桌面 1440px、平板 768px、手机 390px；键盘可操作，表单有可读标签，长文不遮挡按钮。

## 6. 成功指标与范围声明

工程验收：关键测试全通过；一次请求不会重复建任务；越权测试返回拒绝；演示刷新后数据仍在；无模型服务仍能走完流程。

试点观察指标：有效夜晚比例、活动覆盖率、EMA 完成率、同步延迟、每人周任务数、处理时长、联系成功率和退出原因。分母分别定义在数据契约中，不预设未经临床确认的“有效率目标”。

## 7. 边界、风险与假设

- 病种未定：演示数据不标注真实诊断，规则命名只描述变化。
- 设备未定：按模拟适配器开发，不宣称真实可采。
- 患者主动求助是独立路径，不依赖被动规则或基线；演示不联系任何真实个人或机构。
- 真实运行前必须确认人工值班、响应时限、患者可见说明和紧急替代渠道。
- 文献仅支持指标选择方向，不支持本项目阈值；前期材料中的星级不作为正式证据分级。
- 附件仅用于形成需求背景，不复制到仓库，不以机构年度统计训练个体模型。
